# Висновки щодо ефективності алгоритмів пошуку підрядка

У файлі `search_algorithms.py` виконано порівняльний аналіз алгоритмів за часом виконання. Для порівняння використано: `boyer_moore_search`, `kmp_search` та `rabin_karp_search` на основі двох текстових файлів (`article1.txt`, `article2.txt`).

Тестування проводилось при `repeats=100` для двох видів підрядків:
- **існуючий** — підрядок, який дійсно є в тексті;
- **вигаданий** — підрядок, якого немає в тексті.

## Спостереження під час тестування

- для **article 1** найшвидшим був `boyer_moore_search` як для існуючого підрядка (0.0024 с), так і для вигаданого ( 0.0112 с);
- для **article 2** також найшвидшим залишився `boyer_moore_search` (0.0050 с для існуючого, 0.0144 с для вигаданого);
- `kmp_search` показав стабільно другий результат на всіх тестах;
- `rabin_karp_search` був найповільнішим, особливо на вигаданих підрядках через додаткові обчислення хешів і перевірки збігів.

## Висновки

1. **`boyer_moore_search`** показав найкращий час для **article 1**, **article 2** і **в цілому** на обох типах підрядків.

2. **`kmp_search`** працював повільніше за Boyer-Moore, але швидше за Rabin-Karp. Це очікувано для текстів середнього розміру, де KMP проходить текст посимвольно без великих зсувів.

3. **`rabin_karp_search`** виявився найповільнішим у цьому тесті, особливо коли підрядок не знайдено: алгоритм продовжує обчислювати хеші для кожного вікна тексту.

4. **Практичний висновок:** для пошуку підрядків у текстових статтях найефективнішим у нашому експерименті був **алгоритм Боєра-Мура**. KMP може бути корисним, коли важлива передбачуваність часу, а Rabin-Karp — коли потрібно шукати одразу кілька шаблонів або працювати з дуже довгими текстами в оптимізованих реалізаціях.
